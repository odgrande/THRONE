# Deploying Project Throne

```
Visitors ──► Cloudflare (DNS, WAF, rate limits, Turnstile)
              ├─► yourdomain.com      Cloudflare Pages   frontend (static Vite build)
              └─► api.yourdomain.com  Render web service API + live SSE stream ──┐
                                      Render worker      hype video renderer ────┤
                                                                                 ▼
                                      Supabase           Postgres + Storage (images, videos)
                                      Stripe             payments + webhooks ──► API
```

`render.yaml` (repo root) defines both Render services. The frontend and database are set up in their own dashboards.
Do the steps **in this order**: each one produces values a later step needs.
Replace `yourdomain.com` everywhere with your domain.

## 0. Before you start
- Push this repo to GitHub (Render and Cloudflare Pages deploy from it).
- Have your domain's nameservers pointed at Cloudflare (Cloudflare → Add a site).

## 1. Supabase (database + file storage)
1. Create a project. Pick the **US West** region, close to Render's Oregon region.
2. SQL Editor → paste all of `supabase/schema.sql` → Run. This creates the tables, the settlement and archive functions, and the public `media` storage bucket.
3. Settings → API: copy the **Project URL** → `SUPABASE_URL`, and the **service_role** key → `SUPABASE_SERVICE_ROLE_KEY`.
   The service_role key bypasses all security. It goes on Render only, never in the frontend.

## 2. Stripe (start in test mode)
1. Developers → API keys: copy the **Secret key** → `STRIPE_SECRET_KEY` and the **Publishable key** → `VITE_STRIPE_PUBLISHABLE_KEY`.
2. The webhook comes in step 7, once the API has a URL.

## 3. Safety services
- **OpenAI:** create an API key → `OPENAI_API_KEY`.
- **Google Cloud Web Risk:** create a project, enable the *Web Risk API* (needs billing on), and create an API key restricted to that API → `WEB_RISK_API_KEY`.
- **Cloudflare Turnstile:** Cloudflare → Turnstile → Add widget, hostname `yourdomain.com`, mode *Managed* → **Site key** → `VITE_TURNSTILE_SITE_KEY`, **Secret key** → `TURNSTILE_SECRET_KEY`.

## 4. Render (API + video worker)
1. Render → New → **Blueprint** → pick the GitHub repo. It reads `render.yaml` and proposes `throne-api` (Starter) and `throne-video-worker` (Standard, Docker).
2. Fill in every prompted secret:

| Variable | Service | Value |
|---|---|---|
| `PUBLIC_URL` | api | `https://api.yourdomain.com` |
| `SITE_URL`, `CORS_ORIGIN` | api (+ `SITE_URL` on worker) | `https://yourdomain.com` |
| `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` | api + worker | step 1 |
| `STRIPE_SECRET_KEY` | api | step 2 |
| `STRIPE_WEBHOOK_SECRET` | api | type `pending` for now; real value in step 7 |
| `OPENAI_API_KEY`, `WEB_RISK_API_KEY`, `TURNSTILE_SECRET_KEY` | api | step 3 |

`ADMIN_TOKEN` and `ORIGIN_SECRET` are generated by Render. Open the api service → Environment and copy both; you need them in steps 6 and 8.

3. Deploy. The API refuses to start if anything is missing, and its log names the missing keys.
4. api service → Settings → Custom Domains → add `api.yourdomain.com`. Render shows a CNAME target like `throne-api.onrender.com`.

## 5. Cloudflare DNS + TLS
1. DNS → add `CNAME api → throne-api.onrender.com`, **Proxied** (orange cloud).
2. SSL/TLS → mode **Full (strict)**.
3. Wait until Render shows the custom domain as verified.

## 6. Cloudflare origin lock (required)
The API only accepts requests that came through Cloudflare. Without this rule, every request gets `403`.

Rules → **Transform Rules** → Modify Request Header → Create:
- When: `http.host eq "api.yourdomain.com"`
- Then: **Set static** header `X-Origin-Secret` = the `ORIGIN_SECRET` value from Render.

This stops attackers from calling `throne-api.onrender.com` directly to skip the WAF or fake their IP.
`/api/health` stays open so Render's health checks work.

## 7. Payment webhooks

### 7a. Paystack (Nigeria edition)
1. Paystack → switch to **Live Mode** → Settings → **API Keys & Webhooks**.
2. Render → api → Environment: `PAYMENTS_NG=paystack`, `PAYSTACK_SECRET_KEY` = the **live** secret key (`sk_live_…`). Save.
3. Set **Live Webhook URL** to `https://api.yourdomain.com/api/webhooks/paystack` → Save. Paystack signs every webhook with your secret key; the API also re-verifies each payment with Paystack and checks the amount and currency before an ad goes live.
4. Cloudflare: exclude `/api/webhooks/paystack` from WAF challenges and rate limits (Paystack can't solve a challenge). Optionally allow only Paystack's webhook IPs (listed in Paystack's docs) on that path.
5. Make sure your Paystack business is fully activated (KYC done), or live payments are refused.

### 7b. Flutterwave (Global edition, USD)
1. Flutterwave dashboard → Settings → API Keys: copy the **v3 Secret Key** (`FLWSECK-…` live, `FLWSECK_TEST-…` test). Render → `FLUTTERWAVE_SECRET_KEY`.
2. Settings → Webhooks: URL `https://api.yourdomain.com/api/webhooks/flutterwave`; set a **Secret hash** (a long random string) and put the same value in Render → `FLUTTERWAVE_WEBHOOK_HASH`. Tick "charge completed" events.
3. `PAYMENTS_GLOBAL=flutterwave` (the production blueprint sets it). Exclude `/api/webhooks/flutterwave` from Cloudflare challenges.
4. Buyers pay on Flutterwave's page and come back to `/my-ads`; the ad goes live when the webhook arrives and our server has re-verified the payment with Flutterwave.

### 7c. Stripe (Global alternative, only if `PAYMENTS_GLOBAL=stripe`)
If Paystack enables USD for your business, you can use `PAYMENTS_GLOBAL=paystack` instead and skip this part.
1. Stripe → Developers → Webhooks → Add endpoint `https://api.yourdomain.com/api/webhooks/stripe`, event **`payment_intent.succeeded`** → copy the signing secret (`whsec_…`).
2. Render → api → Environment → set `STRIPE_WEBHOOK_SECRET` → Save (Render redeploys).
3. Stripe → Settings → Payment method domains → add `yourdomain.com`. Without it, the Apple Pay button never appears.
4. Turn on the payment methods you want (Apple Pay, Google Pay, cards) under Settings → Payment methods.

## 8. Cloudflare Pages (frontend)
1. Workers & Pages → Create → Pages → connect the repo.
2. Root directory `frontend`, build command `npm run build`, output directory `dist`.
3. Environment variables (Production):

| Variable | Value |
|---|---|
| `NODE_VERSION` | `22` |
| `VITE_API_URL` | `https://api.yourdomain.com` |
| `VITE_MEDIA_ORIGIN` | your `SUPABASE_URL` (lets the CSP load ad images) |
| `VITE_STRIPE_PUBLISHABLE_KEY` | step 2 |
| `VITE_TURNSTILE_SITE_KEY` | step 3 |
| `VITE_ALLOW_CARDS` | `true` (or `false` for wallets only) |

4. Deploy, then Custom domains → add `yourdomain.com`.
   The build emits `dist/_headers` (CSP, clickjacking protection, HSTS), which Pages applies automatically.

## 9. Cloudflare security rules
These rules use Cloudflare's actual expression syntax (`starts_with`, not `cf_string_search`).

**a) Rate-limit bid submissions.** Security → WAF → Rate limiting rules:
- Expression: `(http.host eq "api.yourdomain.com" and http.request.uri.path eq "/api/bids" and http.request.method eq "POST")`
- Count per IP. Block for at least 1 minute once over the limit (e.g. 10 per minute; plan limits decide which periods you can pick).

Don't use a *Managed Challenge* here. The bid form submits with `fetch()`, and challenges can't be solved inside it, so real users' bids would just fail.
The card-testing bot check is **Turnstile**, already built into the form and verified by the API.

**b) Admin lock (only if you have a static IP).** Security → WAF → Custom rules:
- Expression: `(starts_with(http.request.uri.path, "/api/admin/") and not ip.src in {203.0.113.10})`, with your IP in place of the example
- Action: **Block**

Without a static IP, skip this: the admin API already requires the 32+ character `ADMIN_TOKEN`, is rate-limited, and compares the token in constant time.

**c) Leave on:** the Cloudflare Free Managed Ruleset (WAF → Managed rules).
**Bot Fight Mode:** leave it off at first. It's zone-wide and can interfere with Stripe's webhooks. Turnstile covers the bid form.
If you turn it on, watch Stripe → Webhooks for failed deliveries.

## 10. Launch checklist
- [ ] `https://api.yourdomain.com/api/health` shows `store: supabase`, `storage: supabase`, `payments: stripe`, `moderation: true`, `linkChecks: true`, `botCheck: true`.
- [ ] `https://throne-api.onrender.com/api/state` returns **403** (origin lock works).
- [ ] Nigeria edition (`?region=ng`): pay ₦2,000 with Paystack test mode first, then one small live payment. The ad appears on two open browsers within seconds, and Paystack → Settings → Webhooks shows successful deliveries.
- [ ] Global edition: one test payment on its processor.
- [ ] Get outbid from a second browser: the first browser is offered the 50%-off relegation.
- [ ] Place a $20+ bid. Within about a minute, `GET /api/hype` shows a `done` job with a Supabase video URL that plays.
- [ ] `/admin` opens with `ADMIN_TOKEN` and shows **Healthy**.
- [ ] Switch Stripe to live keys (new secret, publishable and webhook secret) and redeploy both API and Pages.

## Costs to expect (check current pricing)
Render Starter (API) + Standard (worker), Supabase Free → Pro once you need backups, Cloudflare Free, Google Web Risk (free tier, then per-call), OpenAI moderation (free endpoint), Stripe per-transaction fees.
**Remotion:** free for individuals and companies of up to 3 people; larger teams need a company license.
